<p>A full rebuild of the 1988 <strong>Norsk Data ND-120</strong> CPU card (the 3202D board) from
the original design documents - first drawn in Logisim-Evolution, now in
Verilog - that runs the original operating system, <strong>SINTRAN III</strong>, on FPGA
boards you can buy today.</p>
<p><strong>Note:</strong> read more about this <a href="https://www.ndwiki.org/wiki/3202" target="_blank" rel="noopener noreferrer">CPU</a> and the rest of the ND range in <a href="https://www.ndwiki.org/" target="_blank" rel="noopener noreferrer">NDWiki</a>, and on the official <a href="http://sintran.com/" target="_blank" rel="noopener noreferrer">Norsk Data</a> site.</p>

<h2 id="readme--overview">🎯 Overview</h2>
<p>This repository holds:</p>
<ul>
<li>the original <strong>Norsk Data ND-120 design documents</strong> from 1988, scanned in 2023;</li>
<li><strong>Logisim-Evolution</strong> schematics of every part of the board;</li>
<li>the <strong>Verilog</strong> version of the whole card, which runs in Verilator and on FPGAs.</li>
</ul>

<p>The five that pass clean on the board - <strong>CONFIGURATION, INSTRUCTION, PAGING,
MEMORY and CACHE</strong> - are the machine's own acceptance suite: the CPU names
itself correctly, runs every instruction group correctly, the MMU translates
and faults correctly, and main memory is sound.</p>
<p><strong>These programs found the real CPU bugs:</strong></p>
<ul>
<li>INSTRUCTION caught a multiply bug (every product's low word was zero) and a
shift bug (all rotate and sign-extending shifts ran as plain shifts);</li>
<li>PAGING caught an MMU fault where the physical-page map RAM was never written;</li>
<li>CONFIGURATION caught a trap-vector fault that sent a page fault plus PGU to an
unused vector, which then jumped to itself forever;</li>
<li>CACHE needed four fixes, all single-input copying errors from the
schematics: the PAL 44511A <code>CWR</code> feedback latch, that PAL's pin-19 polarity,
a dropped Am9150 used-bit write, and a DGA <code>EPANS</code> data-window leak.</li>
</ul>

<h2 id="readme--what-the-cache-is-worth">📊 What the Cache Is Worth</h2>
<p>Measured on the Nexys 4 DDR with the operator panel's own MIPS counter, running
SINTRAN III. The cache is a build option (<code>cache</code> / <code>nocache</code>,
<code>ND120_NO_CACHE</code> - see <a href="https://github.com/RetroCoreLabs/nd-120/blob/main/Verilog/docs/build-defines.md" target="_blank" rel="noopener noreferrer">build-defines.md</a>).</p>


























<table><thead><tr><th>Build</th><th>CPU clock</th><th>Cache</th><th>MIPS running SINTRAN</th><th>Clocks per instruction</th></tr></thead><tbody><tr><td>15</td><td>45.45 MHz</td><td>off</td><td>2.44</td><td>18.6</td></tr><tr><td>16</td><td>33.33 MHz</td><td><strong>on</strong></td><td><strong>> 7.0</strong></td><td><strong>&#x3C; 4.8</strong></td></tr></tbody></table>
<p><strong>The cache gives about 2.9x the throughput - on a clock 26% slower.</strong> This
machine is limited by memory speed, not by the clock: with the cache off, every
instruction fetch is a DDR2 read, and DDR2 does not get faster when the CPU
clock rises. A one-word loop (<code>124000</code>, a <code>JMP</code> to itself) took <strong>17.1 clocks
per instruction</strong> uncached at both 45.45 and 33.33 MHz.</p>
<p>⚠️ <strong>A warning that cost a day:</strong> once the opposite was concluded and the
cache was dropped for speed. The MIPS counter was then counting memory cycles,
so it went blind exactly when the cache started working. Only after it was moved
to a true per-instruction event did the 3x difference show. Prove an instrument
before trusting it.</p>
<p>With the cache in, the routed worst path is 28.039 ns - a ceiling near
<strong>35.6 MHz</strong>. That one path (<code>WRF -> ALU -> TVGEN -> ACAL -> WCS</code> address) is
the most valuable thing to speed up on the board:
<a href="https://github.com/RetroCoreLabs/nd-120/blob/main/Verilog/fpga/nexys4ddr/timing.md" target="_blank" rel="noopener noreferrer">timing.md</a>.</p>

<li>P3 version = 28 pins, 2x 8-bit I/O ports, 1x 4-bit I/O port</li>
<li>U3 version = 40 pins, 4x 8-bit I/O ports</li>
</ul>
<p>We have ROM dumps from both the U3 (from the 3202D CPU board) and the P3 (from
an ND-5000C panel controller), taken apart with
<a href="https://ghidra-sre.org/" target="_blank" rel="noopener noreferrer">GHIDRA</a>: <a href="https://github.com/RetroCoreLabs/nd-120/blob/main/Code/68705/readme.md" target="_blank" rel="noopener noreferrer">ROM dumps and analysis</a>.</p>

<h2 id="readme-about-the-nd-120">About the ND-120</h2>
<p>Norsk Data built the ND-100 range of 16-bit minicomputers. The ND-120 is the
1988 CPU card for that range, print number 3202: it puts the processor into two
gate arrays - the DELILAH CPU gate array and a decoder gate array - where the
earlier ND-110 used discrete TTL chips. It runs the same instruction set as the
ND-110, faster, and can address more memory. Its operating system is
<strong>SINTRAN III</strong>.</p>
<p>The board was designed by Lasse Bockelie and Chris Cherrington. Its original
design documents survived, and that is what makes this rebuild possible: the
machine and its operating system run again, on FPGA boards you can buy today.
More on the card: <a href="https://www.ndwiki.org/wiki/3202" target="_blank" rel="noopener noreferrer">3202 on NDWiki</a>.</p>
